# Управление библиотекой

Начиная с Retro Portal 0.8 владелец сервера и обычный игрок видят **разные интерфейсы**.

- `/` — публичный портал. Здесь отображаются только полностью готовые к запуску игры.
- `/game.html?id=...` — запуск игры, описание, история и настройка клавиатуры.
- `/local.html` — локальный ROM-плеер пользователя. Файл остаётся в браузере и не отправляется на сервер.
- `/admin.html` — кабинет владельца для ROM, BIOS, карточек, метаданных и публикации.

Обычный посетитель не видит сообщения `НЕТ ROM`, `НУЖЕН BIOS` или пути на сервере.

## Первый вход в Library Manager

При первом запуске backend создаёт случайный admin-token, если `ADMIN_TOKEN` не задан в `.env`.

```bash
cat catalog/admin-token
```

Откройте `https://ваш-домен/admin.html` и вставьте токен. В браузере он хранится только в `sessionStorage` текущей вкладки.

Собственный токен можно задать в `.env`:

```ini
ADMIN_TOKEN=очень-длинная-случайная-строка
```

После первого входа повседневное управление библиотекой выполняется из браузерного кабинета.

## Добавление игры

1. Откройте `/admin.html`.
2. Выберите ROM.
3. Для однозначных форматов платформа определяется автоматически.
4. Для неоднозначных `.bin`, `.chd`, `.iso` выберите платформу вручную.
5. Нажмите **Загрузить ROM**.

Backend проверяет допустимое расширение, лимит размера и, где возможно, сигнатуру файла. Оригинальное имя не используется как серверный путь: после загрузки создаётся безопасное имя на основе нормализованного названия и SHA-256.

ZIP-upload в браузере по умолчанию выключен:

```ini
ALLOW_ZIP_ROMS=0
```

Многофайловые CUE/GDI-наборы лучше копировать через SCP/SFTP и затем запускать сканирование.

## Большая библиотека через SCP/SFTP

Разместите файлы в соответствующих каталогах:

```text
games/roms/megadrive/
games/roms/ps1/
games/roms/dreamcast/
games/roms/nes/
games/roms/snes/
games/roms/gb/
games/roms/gba/
games/roms/n64/
games/roms/arcade/
```

Затем откройте `/admin.html` и нажмите **Сканировать**. Новые ROM будут зарегистрированы без ручного редактирования JSON.

## Когда игра появляется у посетителей

```text
ROM найден?
    ↓
Нужен BIOS?
    ↓
BIOS найден?
    ↓
Runtime системы готов?
    ↓
READY → игра появляется на публичном портале
```

Пока обязательный пункт не выполнен, диагностическая информация остаётся только в кабинете владельца.

## PlayStation BIOS

Library Manager умеет распознавать ряд распространённых PS1 BIOS по MD5 и сохранять под каноническим именем, в том числе:

```text
scph5500.bin — JP
scph5501.bin — US
scph5502.bin — EU
PSXONPSP660.bin
scph101.bin
scph7001.bin
scph1001.bin
```

Если карточка ожидает `games/bios/ps1/scph5501.bin`, кабинет показывает это владельцу. Игрок эту зависимость не видит.

## Dreamcast

Для текущего experimental-профиля ожидаются:

```text
games/bios/dreamcast/dc_boot.bin
games/bios/dreamcast/dc_flash.bin
```

Dreamcast остаётся experimental до окончательной интеграции browser Flycast runtime.

## Автоматические карточки, сюжет и история

Retro Portal 0.8 использует безопасную двухэтапную схему: **найти → предложить → подтвердить**.

После импорта ROM портал:

1. пытается сопоставить игру с `catalog/presets/curated-classics.json`;
2. при наличии `THEGAMESDB_API_KEY` ищет название, год, количество игроков, overview и box-art;
3. при `WIKIPEDIA_METADATA=1` пытается получить короткий исторический контекст через фиксированные Wikipedia API hosts;
4. очищает и ограничивает найденный текст;
5. сохраняет результат как `pendingMetadata`;
6. показывает предложение в `/admin.html`;
7. владелец нажимает **Принять** или **Отклонить**.

Пока предложение не принято, оно не заменяет публичное описание игры.

Пример конфигурации:

```ini
THEGAMESDB_API_KEY=ваш-api-key
WIKIPEDIA_METADATA=1
```

Если внешний provider ничего не нашёл, ROM остаётся зарегистрированным и playable при выполненных зависимостях. Метаданные можно запросить повторно.

## Редактирование карточки вручную

В каждой записи Library Manager доступен блок **Редактировать карточку**. Из браузера можно менять:

- название;
- год;
- количество игроков;
- краткое описание;
- историю игры;
- сортировку;
- `featured`;
- публикацию после готовности.

Консоль или ручное редактирование `runtime-games.json` для этих операций не требуются.

## Клавиатура игрока

На странице каждой игры есть кнопка **⌨ Клавиши**. Игрок может сохранить раскладку:

- только для этой игры;
- сразу для всех игр платформы.

Настройки живут в `localStorage` браузера и применяются через поддерживаемый EmulatorJS `EJS_defaultControls`.

По умолчанию используются стрелки для движения, `Z/X` для основных действий, `A/S/D` для дополнительных, `Q/W` для shoulder-кнопок, `Enter` для Start и `Shift` для Select/Mode.

## Реальный online и популярность

Presence-счётчик не является нарисованным числом. WebSocket backend считает активные браузерные сессии и дедуплицирует несколько вкладок одного браузера через локальный session ID.

`/api/activity` отдаёт:

- сколько активных сессий сейчас;
- какие игры реально запущены сейчас;
- количество игроков по каждой игре;
- популярные игры за последние 7 дней на основе реальных launch events.

Если активности нет, интерфейс честно показывает пустое состояние. Fake online/popularity в production не используется.

## Безопасность

Основные правила:

- server-side ROM/BIOS upload доступен только администратору;
- посетительский `local.html` никогда не отправляет выбранный ROM на сервер;
- ZIP upload выключен по умолчанию;
- сервер не распаковывает пользовательские архивы;
- backend не исполняет ROM как OS-программу;
- контейнер backend non-root, read-only, без Linux capabilities и с `no-new-privileges`;
- admin API и public API имеют rate limits;
- metadata download не принимает произвольные пользовательские URL;
- предложенные внешние тексты требуют ручного подтверждения владельца.

Полный threat model: [../../SECURITY.md](../../SECURITY.md).

## Максимальный размер upload

```ini
MAX_UPLOAD_BYTES=2147483648
```

Для больших библиотек предпочтительнее SCP/SFTP + сканирование.

## Права файлов

Backend должен иметь право записи только в рабочие data volumes:

```text
catalog/
games/roms/
games/bios/
public/covers/library/
```

Docker Compose запускает backend с `PUID/PGID` из `.env` и read-only root filesystem.

## Диагностика API

Публичный playable-каталог:

```bash
curl -s http://127.0.0.1:8088/api/games | jq
```

Реальная активность:

```bash
curl -s http://127.0.0.1:8088/api/activity | jq
```

Полный owner-каталог:

```bash
TOKEN="$(cat catalog/admin-token)"
curl -s -H "Authorization: Bearer $TOKEN" \
  http://127.0.0.1:8088/api/admin/games | jq
```

## Правовой момент

Retro Portal не распространяет коммерческие ROM, BIOS или официальные copyrighted artwork. Владелец сервера самостоятельно отвечает за право использования добавленного контента.
